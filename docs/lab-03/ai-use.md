## Reflection

ตลอดการพัฒนา TokTickIT ใน Lab 03 การประยุกต์ใช้ AI ในฐานะ Pair Programmer ได้สร้างการเรียนรู้และมุมมองทางวิศวกรรมซอฟต์แวร์ที่สำคัญในหลายมิติ:

### 1. Specification-Driven Development & Prompt A / Prompt B Pattern

- การเริ่มต้นด้วยการร่าง Engineering Contract ที่รัดกุม (`specification.md`, `api-spec.md`, `ui-spec.md`, `tests.md`) เป็นปัจจัยชี้ขาดความสำเร็จ ทำให้ AI มีกรอบอ้างอิงที่ชัดเจน ไม่คาดเดาหรือแต่งเติม requirements เอง
- การแบ่ง Prompt เป็นสองระยะชัดเจน คือ **Prompt A (Implementation via TDD)** และ **Prompt B (Independent Audit against Spec)** เป็นกลยุทธ์ที่ได้ผลดีมาก เพราะช่วยดักจับข้อผิดพลาดที่ AI หรือผู้พัฒนามักมองข้ามได้ก่อนส่งงาน เช่น การขาด Composite Index ใน migration หรือการเกิด False Error Banner ใน UI

### 2. ความสำคัญของ "STEP 0: Inspect First" และการสืบค้น Root Cause

- กฎเหล็กที่ห้าม AI แก้ไขโค้ดก่อนตรวจสอบโค้ดจริง (Inspect First) ช่วยลดปัญหาโค้ดทับซ้อนและเข้าใจบริบทของโปรเจกต์เดิม
- ตัวอย่างบทเรียนที่ชัดเจนที่สุดคือ **Bug ของการแก้ไข Marcus Reed**: AI ในตอนแรกอาจเข้าใจว่าเกิดจากการเปรียบเทียบ ID หรือ Role ผิดพลาด แต่เมื่อ inspect โค้ดอย่างละเอียดจึงพบ Root Cause ที่แท้จริงว่า `activeAdminsCount` คำนวณจาก `users` ใน client state ซึ่งเมื่อผู้ใช้พิมพ์ค้นหา "Marcus" รายการจะถูกกรองเหลือ 1 รายการ ทำให้ client คำนวณผิดว่า Marcus เป็น Admin คนเดียวในระบบ (`<= 1`) การแก้ปัญหาด้วยการส่ง `X-Active-Admins-Count` Response Header จาก Backend จึงเป็นการแก้ปัญหาเชิงสถาปัตยกรรมที่ถูกต้องและยั่งยืน

### 3. Automated Verification & Confidence ในการส่งมอบ

- การทดสอบครอบคลุมทุกระดับตั้งแต่ Unit Test, Integration Test (Supertest + Prisma) ไปจนถึง Playwright E2E & Responsive Visual Screenshot Audits เป็นตาข่ายรองรับที่ทำให้การแก้ Bug หรือ Refactor โค้ดในภายหลังทำได้อย่างมั่นใจ โดยไม่ต้องกังวลเรื่องการถดถอยของระบบ (Zero Regression) ในส่วนงานเดิมของ Requester, IT Staff และ Administrator
