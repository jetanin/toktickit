## Reflection

ตอน setup โปรเจกต์ครั้งแรกๆ ผมคิดว่าจะติดปัญหาเรื่องเขียนโค้ด business logic มากกว่า แต่พอทำจริงกลับเจอปัญหาเรื่อง environment และ toolchain เยอะกว่าที่คาดไว้มาก โดยเฉพาะเรื่อง TypeScript 7 กับ Prisma 7 ที่เป็นเวอร์ชันใหม่มากและมี breaking change เยอะ (เปลี่ยน output path, บังคับ driver adapter) ซึ่งไม่ตรงกับตัวอย่าง/บทความส่วนใหญ่ที่หาเจอทั่วไปที่ยังอ้างอิง Prisma เวอร์ชันเก่ากว่า

สิ่งที่ผมทำคือ copy error message เต็มๆ ไปถามตรงๆ ทุกครั้ง แทนที่จะสรุปเอง เพราะสังเกตว่าถ้าสรุปเองมักจะข้ามรายละเอียดสำคัญ เช่น path หรือชื่อ error class ที่จำเป็นต่อการวินิจฉัยปัญหา พอทำแบบนี้แล้วได้คำตอบที่ตรงจุดขึ้นมาก และแทบทุกครั้งจะมีคำอธิบาย "ทำไมถึง error" มาด้วย ไม่ใช่แค่บอกวิธีแก้ ทำให้พอเจอปัญหาลักษณะเดียวกันในขั้นตอนถัดไป (เช่น import path ของ PrismaClient ที่ต้องแก้ทั้ง seed.ts และ app.ts) ผมพอจับทางได้เองว่าต้องแก้จุดไหนบ้างโดยไม่ต้องถามซ้ำทุกไฟล์

ในช่วงหลังผมเปลี่ยนมาใช้ Antigravity IDE ที่ทำงานแบบ agentic ได้ คือสั่งงานเป็น task แล้ว AI จะอ่านโค้ด แก้ไฟล์ รันคำสั่ง และรันเทสให้เองจนเสร็จ ข้อดีคือประหยัดเวลาเพราะไม่ต้อง copy-paste ไปมาระหว่าง chat กับ editor แต่ก็พบว่า AI ยังทำพลาดได้ เช่น mock fetch ด้วย Promise ที่ไม่ resolve ทำให้ test ค้าง หรือสร้างไฟล์ไว้ใน src/ แต่ตอนย้ายไป test/ ลืมอัพเดท path ใน config ผมต้องเป็นคนจับจุดพวกนี้เองแล้วสั่งให้แก้

จุดที่ต้องระวังคือ AI ให้คำตอบตามสิ่งที่ผมแปะไปเท่านั้น ถ้าผมแปะ error ไม่ครบหรือลืมบอกบริบท (เช่น เวอร์ชัน Prisma ที่ generate จริง) คำแนะนำที่ได้ก็จะผิดทางไปเลย เช่นตอนแก้ import path ของ PrismaClient ต้องลองผิดลองถูกอยู่ 2-3 รอบกว่าจะเจอ path ที่ถูกต้องจริงๆ เพราะข้อมูลที่ให้ไปตอนแรกไม่ครบพอ สรุปคือ AI ช่วยเร่งการ debug และเขียนโค้ดได้มาก แต่ผมยังต้องเป็นคนตรวจสอบผลลัพธ์และรันเทสยืนยันเองทุกครั้งก่อน commit จริง
